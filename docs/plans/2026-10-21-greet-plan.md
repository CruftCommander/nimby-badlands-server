Greet shows a welcome window after a player spawns: server rules, the Discord invite, how to join, the restart schedule, the mod list, and whatever else Jeff puts in it. The text is a JSON file in the server profile folder, written in a markdown subset, in as many languages as Jeff supplies, and fetched by the client after it spawns, so Jeff edits it without a client update. Each client remembers which version it has dismissed, so a returning player sees the window again only when the text changes and Jeff asks for it, or when the player opens it with the hotkey or from the pause menu. Images and short looping clips ship inside the client PBO and are placed by id from the text. The vanilla hourly `messages.xml` lines stay; the per-mod join lines move into the window once Greet is live.

Two constraints follow from the engine and are stated here so nobody expects otherwise: text changes are live (server file), but every image or clip is a Workshop release, because the client must already hold the file: inside a PBO if Phase 0 item 9 proves a PBO path loads, otherwise as a loose file in the `@NIMBY` folder (G15). Either way the file travels with the Workshop item, never from the server; and nothing inside a `RichTextWidget` is clickable, so a link in the text is always paired with a button (G10).


## What this is not

- Not a rules engine. Greet displays text; it enforces nothing and records nothing about who read it.
- Not a replacement for `messages.xml`. The hourly server messages stay vanilla; only the on-connect join lines move into the window, and only at Greet's release.
- Not a motd that nags. A dismissed window never opens by itself again on that client unless Jeff raises `version` with `forceShow` true (G4). The player can always open it with the hotkey or from the pause menu.
- Not a browser. Links open in the Steam overlay browser through `OpenURL`; Greet renders no web content.
- Not a media channel. Images and clips are release-bound PBO content (G15); the server file only places them.
- Not the Menu addon. Greet has one key binding (G7) and the in-window preferences in G16 and G17, stored in its own `$profile:NimbyGreet\prefs.json`; when Menu exists they register with it. Nothing depends on Menu.
- Not a save-footprint change: no entity data, no `OnStoreSave`/`OnStoreLoad`, no persistent class.

| G4 | Versioning and dismissal | `version` is an integer in `greet.json` that Jeff raises when the text changes. The window has one checkbox, "Don't show this again", off by default (Jeff, October 25, 2026). The window opens by itself at most once per connection: a death and respawn in the same session never re-opens it. Closing with the checkbox on writes `$profile:NimbyGreet\seen.json` with `dismissedVersion` and `neverShow` true. | G5 | Fetch and open | The client drives. After `OnPlayerLoaded` on the controlled player, delayed by a fixed 0.5 s (a client constant, `FETCH_DELAY_MS`, so the request never races `CloseAll()`), the client sends `6551101` (request: a fresh `requestId`, its language code, its `dismissedVersion`, its `neverShow`, `manual` false). The server rate-limits by identity (one request per `requestCooldownSeconds`, default 5; a second inside the window is answered with nothing and logged once per cooldown), refuses a null sender, and answers with `6551102` chunks of the requested language (or `defaultLanguage` when the requested one is absent), each chunk carrying the `requestId`, its `index`, and at most `CHUNK_BYTES` (1,500 bytes, set from Phase 0 item 8) of the serialized `Language` JSON, then `6551103` (done: `requestId`, `chunkCount`, `version`, `forceShow`, `servedLanguage`, the language list, `openDelaySeconds`, `openRetrySeconds`). If `neverShow` is set and `forceShow` is false, or `forceShow` is true but `version` is not above `dismissedVersion`, the server answers `done` alone with `chunkCount=0`, so a dismissed client costs one RPC. The client validates every message (`requestId` equals the one in flight, else dropped and logged under debug; `index` within `0..chunkCount-1`; chunk text at most `CHUNK_BYTES`; `chunkCount` at most `ChunkCount(cap)`; the reassembled JSON at most the G9 total) and treats the payload as complete when all `chunkCount` indices have arrived, whichever order `done` and the chunks take. A new request (hotkey, selector) cancels the one in flight by replacing `requestId`. The window opens `openDelaySeconds` (server value, default 2) after the payload is complete, only if no scripted menu is open (`GetMenu()` is null), the player is alive and conscious, and no automatic open has happened yet in this connection; otherwise it re-checks these local conditions every second (no new RPC) for up to `openRetrySeconds` (server value, default 30), then gives up for this spawn and logs once. The once-per-connection flag lives on `modded class MissionGameplay`, which the client creates on connect and destroys on disconnect (`MissionGameplay` is the mission object; `PlayerBase` is replaced on respawn and cannot hold it). While the window is open, `OnReceivedHit` or `EEHitByRemote` on the controlled player, or falling unconscious, closes it at once with a `close reason=hit|unconscious` line (Jeff, October 25, 2026: a fresh spawn reading rules must not be a blind kill); a health value drifting from cold, hunger, or bleeding never closes it; a vanilla close on death is logged as `close reason=death`. ## Data format

`greet.json` (server, `$profile:NimbyGreet\greet.json`; repository draft at `server/profile-overrides/NimbyGreet/greet.json`):

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `version` | `integer` | Yes | Raised by Jeff on every text change (G4) |
| `forceShow` | `boolean` | No | Default `false`. When `true`, a client that chose "Don't show this again" sees this version once (G4) |
| `defaultLanguage` | `string` | Yes | A key of `languages`; served when the client's language is absent (G14) |
| `languages` | object of `Language` keyed by vanilla column name | Yes | At least `defaultLanguage` (G14) |
| `openDelaySeconds` | `number` | No | Default 2; sent to the client in `done` (G5) |
| `openRetrySeconds` | `number` | No | Default 30; sent to the client in `done` (G5) |
| `requestCooldownSeconds` | `number` | No | Default 5; per-identity rate limit (G5) |
| `rereadSeconds` | `number` | No | Default 10; how stale the server's copy may be before a request re-reads the file (G3) |

`Language`:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `title` | `string` | Yes | Window title, 60 characters maximum |
| `tagline` | `string` | No | One line under the title, 80 characters maximum |
| `sections` | array of `Section` | Yes | 1 to 16 entries (G9); order is display order |

`Section`:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | `string` | Yes | Stable key, `[a-z0-9-]`, 32 characters maximum; logged with every open so a test record can name a tab without quoting its heading |
| `heading` | `string` | Yes | The tab label, 40 characters maximum |
| `body` | `string` | Yes | Markdown subset (G13), 4,000 characters maximum; `\n` for line breaks |

Media (client PBO, `NimbyGreet/Media/`): `<id>.mp4` or `<id>.edds`, `id` in `[a-z0-9-]`, listed in `Media/manifest.json` (`id`, `kind`, `width`, `height`, `durationMs`, `source`, `license`) so the client sizes the block before the file loads and `NOTICE` has one place to read.

`seen.json` (client, `$profile:NimbyGreet\seen.json`):

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `dismissedVersion` | `integer` | Yes | Version shown when the player last closed with the checkbox on, or the version of a forced open (G4) |
| `neverShow` | `boolean` | Yes | `true` once the checkbox has been used; cleared only by deleting the file |

`prefs.json` (client, `$profile:NimbyGreet\prefs.json`): `textScale` (`1.0`, `1.25`, or `1.5`), `playAnimations` (`boolean`), `language` (`string`, empty for detected) (G17).

RPC payloads (`65511xx`):

| Id | Direction | Fields |
| --- | --- | --- |
| `6551101` request | client to server | `requestId` (int, client counter), `language` (string), `dismissedVersion` (int), `neverShow` (bool), `manual` (bool) |
| `6551102` chunk | server to the owning client | `requestId` (int), `index` (int), `text` (string, at most `CHUNK_BYTES` of the serialized `Language` JSON) |
| `6551103` done | server to the owning client | `requestId` (int), `chunkCount` (int, 0 when nothing was sent), `version` (int), `forceShow` (bool), `servedLanguage` (string), `languages` (string, comma-separated list for the selector), `openDelaySeconds` (number), `openRetrySeconds` (number) |

Default `greet.json` written on first boot carries `english` only with placeholder sections (`welcome`, `rules`, `discord`, `restarts`) and the restart schedule from `docs/operations/restart-schedule.md` (so a schedule change is a client release for the default text only, which no live server shows past its first boot); the real text is the repository draft (G12), which Jeff reviews and copies to the host at release.

## Risks

| Risk | Mitigation |
| --- | --- |
| `CloseAll()` in `OnPlayerLoaded` or a later vanilla hook closes the window | Open after `OnPlayerLoaded` with a delay (G5); Phase 0 item 3 records every closer found |
| The connecting dialogue and Greet fight for focus on a slow connection | Greet yields and retries (G5); G-8 proves it |
| A text change is forgotten and `version` is not raised | Returning players see nothing new. Mitigation is a line in the ops doc: raise `version` with every edit; the server logs the version it loaded at every boot |
| Players dismiss the window without reading it | Accepted. Greet is information, not enforcement; the rules also live in Discord |
| Release 1 slips while Greet is built | Accepted by Jeff on October 21, 2026 when he folded Greet into the release. v0.3 widens Phase 1: Phase 0 is a one-day box; Phase 1 is five to six days of build plus the test block (the table block added a day). If that is too long for release 1, the markdown converter, languages, and media can each ship as a later release of the same addon; the window, tabs, links, hotkey, and dismissal are the release-1 core (open question Q4) |
| `RichTextWidget` honors fewer tags than the converter wants | Phase 0 item 7 is the tag sheet; the converter emits only honored tags, and an unsupported construct degrades to plain text, never to a visible tag |
| The RPC ceiling is lower than 1,500 bytes | Phase 0 item 8 measures it; `CHUNK_BYTES` is a constant set from the measurement |
| Two responses interleave (hotkey during the spawn fetch) | `requestId` on every message; a new request cancels the one in flight (G5) |
| A PBO-bundled `.mp4` does not load, or `VideoWidget` costs frame time | Phase 0 item 9; the G15 frame-flip fallback; the clip caps keep any cost small, and animations can be switched off by the player (G16) |
| Media grows the Workshop download | G15 caps (2 MB per clip, 8 clips) and the release-time media list in `NOTICE` |
| Machine translation of the chrome strings is wrong | Marked as unreviewed in `NOTICE`; English is the fallback; a wrong Close label is cosmetic |
| A player dismisses forever, then the rules change | `forceShow` on the version that matters (G4); the pause-menu button and hotkey are always there |
