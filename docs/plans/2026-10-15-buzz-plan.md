# Plan 8 - Buzz (`NimbySmokeFx`)

Draft v0.1, October 15, 2026. Owner: Jeff Fabish. Implementer: a Claude Code session in worktree `feat/buzz`, coordinated by the orchestrator. Status: draft for Jeff's review; implementation waits on Puff Phase 1 (the puff event) being on `main`.

Target: NIMBY | HARDCORE | BADLANDS | 1pp, HostHavoc, DayZ 1.30.164078 / Nasdara.
Release: independent, gated (see [shared rules, 9.2](2026-10-15-shared-rules.md)). Buzz persists nothing, so the content-addon boots in 6.1 do not apply to it; the two cross-addon boots do: Puff without Buzz (Puff PF-012) and Puff with Buzz removed again after a Buzz run (BZ-010).
Feasibility: `docs/design/puff-sprout-scrawl-earplugs-feasibility.md`; where the two differ, this plan is authoritative.

Buzz is what smoking does to the player. It subscribes to Puff's puff event, keeps a per-player level per substance in server memory, syncs the level to the owning client, and renders the effect: visuals through the post-process requesters, cough and laughter through the symptom manager, perks and costs through the stat API, and a smoke cloud around a burning shisha. It exists as a separate addon because every API it touches is the kind a Bohemia update changes; when that happens Buzz is disabled and Puff keeps working.

## What this is not

- Not an item. Buzz defines no entity class and no loot row; it has nothing in `storage_1`.
- Not persisted. Effect levels end on relog and restart. No `ModifierBase` is registered, because a persistent modifier is written to the player save (`ModifiersManager.c:237-244`).
- Not a rule. Costs balance the perks; Jay enforces nothing.
- Not usable without Puff. `requiredAddons[] = {"NimbySmoke"}`; without a puff event there is nothing to do.

## Effects (`survival` profile defaults, tuned in Phase 3)

| Substance | Perk by level | Cost by level |
| --- | --- | --- |
| Tobacco | Level 1-2: warm color grade 60 s; level 2: shock recovers faster for 120 s (mild painkiller) | Level 3: cough chance per puff; water drain plus 10 percent for 300 s |
| Weed | Level 1: slight saturation lift; level 2: slow health regeneration for 180 s; laughter symptom chance | Squint blur 0.10 / 0.20 / 0.35 by level; hunger drain plus 50 percent for 300 s; cough on the first puff of a joint |
| Hash | As weed, one level higher per puff count; level 3: night-vision window (Phase 5) | Squint blur 0.20 / 0.35 / 0.50; cough chance every puff; level 3: radial blur pulse; eyes glow for others during the night-vision window |
| Cloud (passive) | Substance's level 1 perk after 60 s inside, 120 s outside | Substance's level 1 cost; never reaches level 2 without smoking |

The `nudge` profile keeps the visuals and symptoms, replaces the shock and health perks with a stamina-drain reduction (tobacco) and nothing (weed, hash), and halves the costs. The `cosmetic` profile zeroes every stat value. Every number is a `config.json` field; the tables are the shipped defaults.

## Phase 0 - prove the hooks

Depends on Puff Phase 1 on `main`.

1. Record builds and reference hashes in `docs/baselines/`.
2. Subscribe to the puff event from a throwaway Buzz script and confirm receipt with the payload on the server.
3. From the server, send RPC `6550801` to the owning client and request `PPERequester_SquintEffects.SetBlur(0.2)`; confirm it renders and clears; repeat for a color-grading requester and radial blur.
4. Queue `SYMPTOM_COUGH` and `SYMPTOM_LAUGHTER` from the server and confirm both play.
5. For each stat in the Effects table, cite the 1.30 call (file:line) and confirm one change in game: shock, health regeneration, hunger drain, water drain, stamina drain.
6. Spawn an `EffectTrigger` subclass at a placed item, walk in and out, and record which of `IsSoundInsideBuilding()` and `IsUnderRoof()` is true in three Nasdara structures and in the open.
7. Play `ParticleList.HOUSE_SMALL_SMOKE` at the placed item and record visibility at 10 m and 30 m.
8. Request `PPERequester_CameraNV` in one mode at night and confirm it renders and clears; attach a scripted light to the head bone of a second client and confirm the first client sees it.

Exit: every row above has a yes or no with evidence. A "no" on item 2 or 3 stops the plan.

## Phase 1 - effect service

- Addon skeleton: `config.cpp` (`CfgPatches` requiring `DZ_Data` and `NimbySmoke`), `Scripts/3_Game` (RPC ids, config model), `Scripts/4_World` (service, subscriber, stat application), `Scripts/5_Mission` (client receiver), `NOTICE`.
- Service per B2 with the tobacco profile; server log per level change with both player ids (shared rules 4.2); config per B6.
- Client receiver per B7 rendering the tobacco color grade.
- Self-test: level arithmetic, decay, substance reset, profile selection, config parsing with defaults.
- `pack.json` row added by the orchestrator.

## Phase 2 - full effects and profiles

- Weed and hash substances; squint, saturation, radial blur; cough and laughter; the three `perkClass` profiles (B3).
- Debug flag `$profile:NimbySmokeFx\debug` per shared rules 4.3.

## Phase 3 - cloud, particles, tuning, release

- `NimbySmokeFx_CloudTrigger` (B4) with the configured cap; particle class `NimbySmokeFx_ShishaSmoke` on vanilla smoke textures, emitter count doubled for hash.
- Tuning playtest with Jeff and Jay on the local test server: every value in the Effects table reviewed and the agreed values written back to this plan and to the shipped `config.json` defaults.
- Release gate per shared rules 9.1 and 9.2, plus BZ-010.

## Phase 5 - night vision

- Hash level 3 window per B5; the glow light; both off in the `cosmetic` profile; config seconds for the window.
- Phase 4 is intentionally unused so the phase numbers line up with Puff and Sprout.

## Risks

| Risk | Mitigation |
| --- | --- |
| Stat API differs from the 1.29 shape | Phase 0 item 5 cites each call before Phase 1 |
| Effects too strong for hardcore | `perkClass` is one config value; Phase 3 playtest before release |
| Trigger count under load | Config cap on burning shishas; the trigger exists only while burning |
| A Bohemia update breaks a requester | Buzz is removed from `pack.json`; Puff keeps working (PF-012) |
| Night vision unbalances night play | Window length and level threshold in config; off in `cosmetic` |
