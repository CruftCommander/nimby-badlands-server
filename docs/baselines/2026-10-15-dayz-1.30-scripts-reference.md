## Where the key bindings are

The plans refer to "the unpacked 1.30 `inputs.xml`". There is no file of that name in 1.30. The
PC default bindings live in `bin/preset_X1MouseKey.xml`: `bin/core.xml` lines 4-7 name
`preset_X1MouseKey.xml` as `#STR_UAPRESET_PC_0`, the main PC preset. Action and button names are
declared in `bin/constants.xml`. Read "inputs.xml" in any plan as those two files.

What the 1.30 preset says about the candidate keys in shared rules section 5 (recorded here as
reference, verified in each plan's Phase 0):

| Key | `preset_X1MouseKey.xml` | Note |
| --- | --- | --- |
| `kAdd` (numpad plus, Legs A3) | Line 976, under `UABuldZoomIn` (line 975) | Bound to a `UABuld*` builder input. Legs Phase 0 confirms whether `UABuld*` inputs are live on a release client before treating numpad plus as free |
| `kO` (Gimme offer/request) | Not bound | Free in vanilla; the collision was Gimme's own Shift+O (resolved by G2) |
| `kHome` (Golden God N2, first candidate) | Not bound | Free in vanilla |
| `kEnd` (N2, second) | Not bound | Free in vanilla |
| `kF10` (N2, third) | Lines 446 (`UAGestureSlot10`), 480 (`EmoteThroat`), 824 (`UABuldRunScript`) | Taken by the gesture wheel and an emote |

Under N2's rule (first verified-free wins) Home is the Golden God default unless Phase 0 finds
otherwise.

## Rules

- Nothing in `vendor/dayz-1.30-scripts/` is edited. The folder is read-only on disk and
  git-ignored; a session that needs a vanilla file changed copies it into its own addon.
- Cite as `vendor/dayz-1.30-scripts/<path>:<line>` in plans, tests, and commit messages.
- After a DayZ update: re-run the extract to a new folder named for the new version, re-hash,
  write a new baseline, and update section 7 of the shared rules to point at it.
