## Findings

- **NIMBY-T-069 (open, blocker).** `NimbyDpv_Car` reports `WheelCount()=4`, `WheelGetEntity(i)` returns the attached `NimbyDpv_Wheel` for every hub, but `WheelCountPresent()=0`, `WheelHasContact(i)=false` and `WheelGetPositionLS(i)=<0,0,0>` for all four. The simulation finds the entities through the slots but never resolves the hubs. Ruled out tonight, each by a run: config AnimationSources and turn/damper/steering-wheel sources; `Sounds` class (a warning only, the ADA has none); `vehiclepart` class property on the wheel P3D; LandContact LOD (removed, neither reference has one); wheel View and Fire Geometry LODs (added, as the Arma2Quad wheel has); slot-named selections in View Geometry and Memory (added, as the ADA has); stray `wheel_x_y_damper_land` memory points (removed); MLOD versus ODOL (binarized with DayZ Tools `binarize.exe`, same `present=0`). Still different from the two working references: hub components are 8-point boxes where the ADA and Arma2Quad use 24-point cylinders of about wheel-hub size, `wheelHubRadius` 0.16 against the quad's 0.35, and the DPV wheel item config was never compared field by field against `HatchbackWheel` (`physLayer`, `itemSize`, `lockType` and `DamageSystem` are inherited from `CarWheel`, so they should match). Next step is in NEXT.md.
- **NIMBY-T-070 (closed).** 1.30 `CarWheelType::SetReplacementTypes` throws a VM exception for any wheel class without a `<class>_Ruined` config entry; the first `CreateInInventory` lost a wheel. `NimbyDpv_Wheel_Ruined` (config and script, reuses `dpvwheel.p3d`, radius 0.22) added; self-test case `wheel-ruined-class-exists`.
- **NIMBY-T-071 (closed).** The proxy triangle's short leg must run along minus forward (long leg up, origin at the right angle). Confirmed against the Arma2Quad crew proxy, which points its short leg at the quad's rear. With the short leg along plus forward the driver faced the rear.
- **NIMBY-T-072 (closed).** `binarize.exe` merges every `model.cfg` under the source folder. A stale copy under `data\mods\...` (left by an early robocopy with a relative path) supplied an old `dpv_skeleton` with `light_left`/`light_right` bones and no crew bones, which the engine reported as `Proxy with bone name 'crewDriver' was not found in view geometry`. Folder moved to `D:\DayZProjects\_stale-dpv-robocopy-copy`; delete it.
- **NIMBY-T-073 (closed).** Crew proxies need a skeleton bone of the same name (`crewdriver`, `crewcodriver`, `crewcargo1`) or the player is seated at the model origin.
- **NIMBY-T-074 (closed).** The engine's steering-wheel animation source is `steeringwheel`, not Arma's `drivingWheel`; the front-wheel turn animations use the `animTurn` names as their source (`turnfrontleft`, `turnfrontright`), not `user`; wheel spin uses `wheelfrontleft` etc. Confirmed by the ADA's embedded animation table (`DrivingWheel` with source `steeringwheel`).
- **NIMBY-T-075 (closed).** `wheelHub="wheel_x_y_damper_land"` names a Geometry LOD component; without it the engine logs `Won't simulate, wheel wheel_1_1_damper_land has no proper selection in geometry` and `Cannot create non-ai vehicle`.
- **NIMBY-T-076 (closed, tooling).** `Start-NimbyTestClient.ps1` needs the client build; `Get-ChildItem .\build -Filter '@NIMBY-2*'` picks it (the `@NIMBY-Server-*` folder sorts last under `@NIMBY-*` and the client is then kicked for the missing server PBO).
- **NIMBY-T-077 (closed, tooling).** A build run while the previous test server is still up ends `UNKNOWN` and the next join lands on the old server; stop the server (Enter in its window) before building.
- **Open: seat height.** With the crew proxy at the cushion point (0.85 m) the driver's head sits at 1.54 m and Jeff reports it as too high; the ADA seats him at 0.84/1.53 and looks right, so the DPV's own seat geometry is lower than the proxy. Lower the crew origin by about 0.15 m once the wheels work.
- **Open: driver side.** The driver proxy was placed at model x=-0.32 but the seated root logs at x=+0.33 on every run; the steering wheel is in front of him there. Which side is the DPV's steering wheel in the built model was never confirmed in game; check in Object Builder before trusting the mirrored result.
