## Findings

- **NIMBY-T-037 (RPC string cap, G5).** A string inside an RPC `Param` arrives intact at 1,000 bytes and throws `Virtual Machine Exception: !!! String CORRUPTED - FIX OnStoreLoad() !!!` in `ParamsReadContext.Read` at 1,100 bytes and above, for ASCII, Cyrillic and CJK alike, so the cap is on bytes, in (1,000, 1,100]. The RPC itself is delivered (the `done` record after it arrives) and nothing kicks the client, but every oversize chunk is a `SCRIPT (E)` in the client log: 895 of them in run 1. `CHUNK_BYTES` is 1,000 (`53dea79`); the plan's 1,500 was wrong. A 40,359-character Russian language is 74 chunks and arrived in 1.6 s and 3.2 s on the LAN.
- **NIMBY-T-038 (video, G15 stop condition).** `VideoWidget` fired `ON_ERROR` for every clip and path tried on the 1.30 PC client in game: PBO paths with both slash styles, `$profile:`, and the vanilla-style game-root `video\` folder; H.264 High and Constrained Baseline with and without an AAC track, and MPEG-4 Part 2. `GetState()` never left `NONE`; `Load` and `Play` return `true` regardless (deprecated, `EnWidgets.c:547`). No video file of any kind ships in the PC install, so there is no reference encoding to copy and no evidence that `VideoWidget` decodes anything on PC. G15 falls to the frame-flip fallback (`ImageWidget`, `LoadImageFile` 0 to 7, timer-driven); `.edds` loading from the PBO is proven (G-P0-37).
- **NIMBY-T-039 (focus, G5/G6).** A `UIScriptedMenu` shown with `ShowScriptedMenu` takes the cursor and the UI focus but does not stop the player: WASD, item pickup and doors all work with the window open (Jeff, run 2). Vanilla pairs a scripted menu with `g_Game.GetMission().AddActiveInputExcludes({"menu"})` (`PlayerBase.c:5812,5822` for the warning dialogs); the `menu` exclude set is `inventory` plus `hotkey` plus `movement` plus the gear and voice inputs (`bin/specific.xml:277`). Phase 1 adds the exclude on show and `RemoveActiveInputExcludes({"menu"})` on hide (the N11 lesson: remove exactly what was added, and not when another menu underneath owns it). `UANimbyGreetOpen` is not in the set, so Insert still toggles.
- **NIMBY-T-040 (markup, G13).** Honored: `<b>`, `<i>`, `<color hex="0xAARRGGBB">`, `<color rgba="r, g, b, a">`, `<p>`, `<br/>`, and `\n`. Consumed but not honored: `<u>` (no underline), `<font size>` (swaps to a fallback face, ignores the size), `<image set name scale>` (nothing drawn for `dayz_gui`/`externallink` in this context). No entity is honored (`&lt;`, `&#60;`, `&amp;` print as typed). A raw `<` swallows everything to the next `>`, across tags, so one stray `<` in `greet.json` can eat a line and its `<br/>`; `<<b>>` prints `>...>`. An unterminated `<b>` bleeds to the end of the whole text. Of the look-alikes only `‹` and `›` (U+2039, U+203A) have glyphs in `sdf_MetronLight24`; fullwidth, modifier and math brackets, and CJK text, render as boxes. Consequences for G13: links are not underlined (the `[n]` marker and the link color are the cues); headings use `<b>` and the body's own `SetTextExactSize`, not `<font>`; the converter replaces `<` and `>` with `‹` and `›` before anything else, always closes what it opens, and CJK languages need a font check before any CJK column ships (G14).
- **NIMBY-T-041 (scroll).** `SetContentOffset` accepts any value: the offset ran to 240 on a 146-pixel body and to 1,680 on a 5,762-pixel one without clamping. The Phase 1 scroller clamps to `max(0, contentHeight - paneHeight)`; `GetContentHeight` and `GetNumLines` are reliable (120 source lines wrapped to 240 at 817 pixels of pane).
- **NIMBY-T-042 (malformed `greet.json`, G3).** `JsonFileLoader.LoadFile` returns `false` with a readable message and the server keeps running and serving, but the engine's serializer also prints `SCRIPT (E): JSON ERROR <file:line>` to the script log. On the live host that is a `SCRIPT (E)` in the RPT, and on a release-gate boot it is a gate failure. `scripts/Test-GreetText.ps1` (G12) is therefore mandatory before any upload, and the `.lkg` copy stays.
- **NIMBY-T-043 (stills, G15).** DayZ Tools ImageToPAA refuses a non-power-of-two source (`Error (Img is not of power of 2 size)`); 512x256 converts to a 7.8 KB `.edds` that `LoadImageFile` loads from the PBO path (`NimbyGreet/Media/probe.edds`, `size0=512x256`). An `ImageWidget` without `"no wrap" 1` tiles the texture. Frame-flip clips are therefore power-of-two frames, up to 8 per widget.
- **NIMBY-T-044 (language, G14).** A `stringtable.csv` at the PBO root loads without any `config.cpp` reference; `Widget.TranslateString("#STR_NimbyGreet_Language")` returns the column text for the client's language (`english`); an unknown key returns the key without its `#`; `ListOptionsAccess.GetItemText` returns the option's untranslated key (`#options_language_EN`), so it is not a language name source. `GetCurrentDisplayLanguageIdx` is 0 for English. The German read (G-P0-40) is still owed.
- **NIMBY-T-045 (links, G10).** `GetGame().OpenURL` opens the system default browser (Edge here), not the Steam overlay, with the overlay enabled; from there Edge handed the invite to Discord Desktop. R8 is met in the sense that matters (the invite opens); the plan's "overlay browser" wording is wrong. `CopyToClipboard` round-trips through `CopyFromClipboard`.
- **NIMBY-T-046 (hotkey under focus, G7).** A `UAInput.LocalPress` fires while a `UIScriptedMenu` holds focus, and both `MissionGameplay.OnUpdate` and the menu's own `Update` see the same press in the same frame. Phase 1 reads the key in one place only (MissionGameplay) or the toggle double-fires.
- **Cosmetic, probe only.** The probe layout's button labels clip (the `Default` button style's text is larger than the slots); the still tiled in run 1. Neither is carried into Phase 1, which builds its own layout.
