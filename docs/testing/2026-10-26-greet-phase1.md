## Findings

- **NIMBY-T-049 (cooldown refusal was silent, G5).** The per-identity rate limit answered a request inside `requestCooldownSeconds` with nothing, so a language switch (or an Insert press) within 5 s of the last fetch left the window waiting on a response that never came; the next click inside the window was refused again. Fixed: the refusal is a `done` with `chunkCount=0`, `reason=cooldown` and `retryAfterSeconds`; the client schedules one retry of the same request after that time (`m_NimbyGreetRetryPending`, cleared by any newer request). The log line `request refused reason=cooldown` stays, once per cooldown. Plan G5 and test G-24 amended.
- **NIMBY-T-050 (mod string table after an in-session language change, G14).** Changing the game language in Options without restarting the client left `Widget.TranslateString` returning the bare keys for Greet's table while vanilla strings switched; after a client restart the German column resolved. Fixed: `NimbyGreetMenu.Tr(key, fallback)` returns the English text when the engine returns a key, so the window degrades to English, never to `STR_` names. The body text was never affected (it comes from the server).
- **NIMBY-T-051 (the spawn open gave up behind the pause menu, G5).** Vanilla opens the pause menu at spawn when the game window is not active (`missionGameplay.c:296-310`: on the first update, `!g_Game.IsAppActive()` queues `Pause()`, which runs once the player is loaded). Greet correctly never draws over it, but it counted that wait toward `openRetrySeconds` and gave up after 30 s (client 07:40:45 to 07:41:17.363, `open deferred` #1 to #120 with `menu=9`, then `open gave up after 120 retries source=spawn menu=9`), so a player who switches windows during a long load and lingers in the pause menu never gets the window on that connection. Jeff, October 26, 2026: time behind the pause menu does not count; other menus keep the limit. Fixed after run 5's first tests in `NimbyGreetRules.OpenWaitCounts` (three self-test cases) and the open loop, which logs the uncounted wait once; `OnMissionFinish` now also removes a queued open from the call queue, since the wait is no longer bounded. Plan G5 amended.
- **NIMBY-T-052 (client crash after a disconnect within 20 s of a request, G5, G-21).** Jeff pressed Insert at 08:42:23.030 (`request sent id=2 manual=true`), logged out to the main menu (`mission finished` 08:42:40.999, `intro.Nasdara` loaded 08:42:41.367) and the client crashed at 08:42:43: `Access violation.
